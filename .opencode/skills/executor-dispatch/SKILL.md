## When to use

【大脑】已生成 `Docs/Handoff/TASK_XXX.md`，用户说“派单”或“执行”时（可经 `executor` 子代理）。

## 步骤

1. 派单内容只含：工单文件路径 + “只读该工单文件，禁翻其他文档” + 风险等级。工单须自包含，不得写“参见 CURRENT.md”。
2. 执行者只读工单文件；信息不足在 REPORT 声明“信息不足”，不自行翻阅其他文档。
3. 涉及代码/资产修改：动手前先输出“受影响文件与符号清单”（含字符串引用、场景引用、`.meta`），等用户确认。
4. 任何 Unity 操作（批处理、烘焙、资产写入）前：请求用户关闭编辑器，并等待明确确认已关闭；如需隔离副本，先告知并说明代价。
5. 修复/新功能：先写失败测试（red）→ 再实现到全绿；间歇性/时序问题 N≥3 次重复运行。
6. 日志/大文档只用 `grep` / `Select-String -Context 2` 定向提取；超 50 行只留计数 + 前 10 条示例。
7. 写 `Docs/Handoff/REPORT_XXX.md`：结果摘要、改动文件清单、测试/检查结果（断言+数据+原始日志路径）、遗留问题、实现原理（修复/功能单）、受影响模块导航说明、建议提交（格式见 `Docs/Handoff/workflow-rules.md`）。

## 失败路径

- 无法复现 → 写“无法复现”+ 建议复现步骤，不编造根因。
- 需求矛盾或越出工单范围 → 停下提问。
- 用户未确认关闭编辑器 → 不操作 Unity。

## 验证

- 执行者未进行任何 git 写操作（`Docs/` 纯文档且用户“批准提交”除外）。
- 改动文件全部在工单授权范围内；REPORT 中的每项结论有日志/断言/diff 支撑。
