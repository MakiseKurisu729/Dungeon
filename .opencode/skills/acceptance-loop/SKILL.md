## When to use

执行者提交 REPORT 后，用户说“复审”“验收”时。

## 步骤

1. 一次性读完：对应 TASK、REPORT、QA 表相关行。
2. 证据三件套核查，缺一即不通过：
   - **REPORT**：必需节齐全（含实现原理、受影响模块导航说明、建议提交，按工单类型）。
   - **断言数据**：断言 ID、实际数据、原始日志路径真实存在；重复运行次数达标（常规 ≥2，间歇性/时序 N≥3），结果不一致标“不稳定”。
   - **git diff**：只读执行 `git status --short` 与 `git diff --stat`，确认改动文件均在工单授权范围内，无场景/预制体/Animator/ProjectSettings/`.meta` 越权改动。
3. 按风险等级：中风险须用户送外部顾问复核后再终审；高风险须外部顾问 +【大脑】双重终审。
4. 给出结论（通过 / 退回 + 缺项清单，≤300 字），并更新 `Docs/Handoff/CURRENT.md` 登记批次。

## 失败路径

- 证据缺失或与 REPORT 不符 → 退回，不替执行者补写结果。
- 人工目检未由用户填写 → 标“待目检”，不得预填。
- 发现与基线矛盾 → 停止并报告。

## 验证

- 复审结论每条可追溯到具体日志行、断言或 diff。
- 未修改 `Docs/Handoff/` 以外的文件。
