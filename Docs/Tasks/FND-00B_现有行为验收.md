## 1. 唯一主要结果

形成一份**由用户描述和 Unity 实际复验支持**的现有行为矩阵。矩阵中每一项都有明确的"通过 / 失败 / 部分通过 / 未测试"结论与证据出处。

## 2. 非目标

- **不修复**验收中发现的任何问题。
- 不改代码、不重构、不调整场景/预制体/Animator/资产。
- 不做原因分析。
- 不提出修复方案。
- 不做架构改造。
- 只记录复现步骤、观察到的现象、结果和证据。
- 为验收不得临时把宝箱、传送点或其他对象加入场景；当前场景不具备条件时记录"未测试／当前场景不可验收"。
- 不开始 Unity 6.3 迁移。
- 不安装新包。

## 3. 读写权限

| 类别 | 内容 |
|---|---|
| 允许读取 | 运行中的 Unity 编辑器、Game 视图、Console；`Docs/00`、`Docs/QA`、当前任务包 |
| 允许修改 | `Docs/QA/FND-00B_现有行为验收.md`、`Docs/QA/Evidence/` 下的证据文件、`Docs/00` 中对应条目的状态与来源 |
| 禁止修改 | 除上述文档与证据外的任何文件；特别是代码、场景、预制体、Animator、`ProjectSettings`、`Packages`、`.meta` |

## 4. 架构与兼容约束

- 只记录观察到的现象，不推测为结论。
- 与 `Docs/00_项目事实基线.md` 第 3.1 节逐条对应，不新增无来源的"已实现"判断。
- 结论必须可追溯到具体操作步骤与证据文件（若无证据，写明"无证据，仅口头确认"）。

## 5. Unity 编辑器影响

- 需要打开 Unity：**是**（用户操作）。
- 允许在编辑器中进入 Play 模式做验证。
- **任何编辑器内的改动都不得保存**（不保存场景、不应用预制体修改）。
- 不需要重新构建（除非用户另行决定）。

## 6. 执行预算

- 按第 7 节的顺序一次性走完一轮；失败项不展开修复。
- 单场景重复尝试上限：每项最多 3 次，之后如实记为"失败"或"部分通过"。
- AI 侧只负责提问、记录、整理，不做代码探索。

## 7. 验收顺序

严格按下列顺序执行，前一项阻塞时记录并继续下一项：

1. 启动与场景
2. 移动与镜头
3. 普攻与技能
4. 动画表现
5. 宝箱
6. 迷雾
7. 救援
8. 传送
9. 团灭与游戏结束

## 8. 操作分工

- **用户**：在 Unity 中执行全部操作，描述观察到的现象，判定结果。
- **AI**：逐项提问（场景、前置状态、步骤、预期、实际），把回答写入 `Docs/QA/FND-00B_现有行为验收.md`，维护证据命名与链接。
- AI **不得**代替用户下"通过"结论。

## 9. 验收方式

- 每项按统一字段填写：测试场景 / 前置状态 / 操作步骤 / 预期结果 / 实际结果 / 结果 / 证据 / 备注。
- 结果取值仅限：`通过`、`失败`、`部分通过`、`未测试`。
- 完成后由用户确认整份记录真实无误。
