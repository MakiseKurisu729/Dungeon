# Constitution — 魔石地牢

> 课程《Spec-Driven Development with Coding Agents》的 constitution 在本项目的最小落地：只写**判据与索引**，**不复制** `00` / `01` / `02` 的内容。
> 事实回 `Docs/00`，架构回 `Docs/01`，计划回 `Docs/02`。维护规则见 §6。

## 1. Mission（为什么做）

- **是什么**：魔石地牢 —— 单机可演示的 3D 动作地牢原型（编队 → 探索 → 战斗 → 撤离）。
- **为什么做**：毕业设计交付物，需要可稳定演示的 MVP 闭环，以及能当场讲清的技术决策链。
- **给谁看**：答辩老师（完整性、可维护性、可解释性）、玩家（能玩通一轮）。
- **成功标准**：MVP 闭环可重复演示，不崩、不卡死；关键机制能被所有者用自己的话讲清。

## 2. Scope / 非目标

**MVP 闭环（目标）**

```
走图 → 遇怪 → 普攻 / 技能 → 宝箱 → 团灭 → R 重来
```

**非目标（本轮）**

- 联机 / P2P 同步
- 多楼层与三层地牢内容
- 大重构、换框架、装新包、目录迁移（**例外**：所有者 2026-11-06 批准的 M7 结构收口，范围见 `Docs/交接/当前状态.md`）
- Unity 6.3 迁移（属目标版本，本轮不动）

## 3. Tech stack

| 项 | 事实 |
|---|---|
| 引擎 | Unity `2022.3.62f3c1`；目标 `6.3 LTS` 但**尚未迁移** |
| 语言 / 结构 | C#；模块化单工程、组件化 GameObject、数据驱动内容 |

| 验证 | `Assets/_Project/Tests/` 自动化断言 + `Docs/QA/Evidence/` 证据 |
