## 4. 自动化验收标准

### 子项 11：传送（现有行为观察）

至少实现并输出：

- [ ] `Teleport.EntryCensus`：枚举当前场景中可辨认的传送入口/组件，输出数量、对象路径、激活状态和交互组件状态；未发现时明确输出 `count=0`，不得推断“代码不存在”。
- [ ] `Teleport.TargetData`：存在入口时输出源点坐标、配置目标坐标、目标场景/对象标识（按实际实现）及目标是否有效。
- [ ] `Teleport.ReachesTarget`：通过实际交互入口触发，断言角色到达配置目标坐标容差范围内；输出交互前后坐标、目标坐标、距离误差和事件链。不得用测试直接设置终点坐标冒充交互结果。
- [ ] 目标设计仍未明确：无入口时只形成 `OBSERVED_NO_ENTRY` 等客观观察结果，不把“枚举成功”当成功能通过；若无法作通过/失败判定，QA 保持 `未测试` 并说明，不得强行改判。

### 子项 12：团灭与游戏结束（含怪物遭遇前置数据）

至少实现并输出：

- [ ] `Monster.Population`：在团灭夹具前输出初始怪物数量、固定观察窗口内新增生成数量、怪物 ID 与位置、生成器数量/状态；生成数量为 0 必须原样输出。
- [ ] `Monster.NavMeshState`：逐只输出 NavMeshAgent enabled、`isOnNavMesh`、`pathPending`、`hasPath`、位置与观察窗口内位移；数据不足时标未确认，不把“未生成或怪物无法移动”任一可能写成原因。
- [ ] `Monster.EncounterProbe`：沿可重复观察路径或固定观察窗口记录遭遇事件数、最近距离及怪物位移；断言数据已完整采集。该探针只复核差距，不扩展为怪物 AI 修复。
- [ ] `Party.AllDown`：通过实际伤害/倒地状态入口建立全员倒地，逐角色输出 ID、倒地时间、状态与存活计数；不得直接调用 GameOver。
- [ ] `GameEnd.TriggerChain`：按时间顺序输出 `角色倒地 → aliveCount=0 → 游戏结束事件/状态 → UI 状态` 的触发链，断言全员倒地后在限定时间内触发且仅触发一次。
- [ ] `GameEnd.FinalState`：输出最终游戏状态、相关 UI active 状态和输入锁定状态；未触发须输出等待时长及实际状态，不得写成通过。
- [ ] 怪物遭遇前置失败时仍可用独立团灭夹验测试游戏结束链，但报告必须分开标注“遭遇探针结果”和“团灭链结果”，不得相互掩盖。
