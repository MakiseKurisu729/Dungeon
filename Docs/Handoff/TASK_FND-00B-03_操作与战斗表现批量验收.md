- 只产出 **一份合并报告**：`Docs/Handoff/REPORT_FND-00B-03_操作与战斗表现批量验收.md`。

- 不修改 `Assets/`、`Packages/`、`ProjectSettings/`、代码、场景、预制体、Animator、`.meta`；不重新烘焙、不安装包、不构建、不升级 Unity。
- 不测试宝箱、迷雾、救援、传送或团灭，不为动画验收主动制造全员倒地。
- AI 不执行 Git 变更操作。前置失败则不进入 Unity，只写合并报告说明停止。

允许写入：`Docs/QA/Evidence/FND-00B-03/`、QA 的当前状态及第 2～6 项与汇总、上述合并 REPORT。不得修改 `CURRENT.md`。

## 3. 一次会话内的按序清单

### 子项 2：移动

- [ ] 选中 1 个可操控角色，记录名称与起始位置；对明确地面目标下发 1 次移动指令。
- [ ] 记录响应、位置变化、路径、目标附近停步及移动过程中的镜头跟随；失败时不反复尝试。
- [ ] 证据：`02_移动_开始.png`、`02_移动_结束.png`。

### 子项 3：镜头

- [ ] 在已选中角色状态下按住左键拖动，记录视角是否可拖动及实际表现。
- [ ] 本子项只测左键拖动，不把移动时的镜头跟随结果代替本项。
- [ ] 证据：`03_镜头_拖动后.png`。

### 子项 4：普攻

- [ ] 选中角色并对附近 1 个敌人执行普攻指令，记录接敌、出招、是否持续攻击及伤害结算。
- [ ] 记录实际目标与客观数值/血条变化；未观察到就写未观察到。
- [ ] 证据：`04_普攻_结果.png`。

### 子项 5：技能

- [ ] 先记录当前场景实际存在的职业及可确认的技能，再对当前可用且冷却完毕的技能逐项操作。
- [ ] 记录技能名称、释放是否成功、范围与效果；骑士盾击仍须实测，不可用或无法确认的技能明确标注。
- [ ] 证据：`05_技能_结果.png`（多个技能可用 `_02` 等后缀追加）。

### 子项 6：动画表现

- [ ] 汇总本次会话已观察到的角色待机、移动、攻击、受击、死亡状态；缺失状态可在本项末尾单独触发，但不制造团灭。
- [ ] 按“角色/单位—动画状态—是否播放—对应操作—证据”记录；未触发写“未观察”，不得由用户报告推断。
- [ ] 证据：`06_动画表现.md`；必要截图命名为 `06_动画_<状态>.png`。

- [ ] 保存 `01_会话开始_Console.png`、`99_会话结束_Console.png`，并将各阶段实际 Console 文本按子项写入 `Unity_操作与战斗.log`；异常须保留完整文本与堆栈。

- [ ] 退出 Play 时不保存场景或资产变化。某子项被前序状态阻塞时，仍须写明已尝试、被阻塞或未测试及原因现象，再继续可独立观察的后续子项；不得静默跳过。
