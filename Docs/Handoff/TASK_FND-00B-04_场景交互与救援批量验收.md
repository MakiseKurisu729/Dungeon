## 4. 自动化验收标准

### 子项 7：宝箱

至少实现并输出：

- [ ] `Chest.SceneCount`：当前场景宝箱实例数量、对象路径、位置、`activeSelf/activeInHierarchy`、交互组件 enabled 状态。
- [ ] `Chest.Interactable`：存在可交互实例时，通过实际交互入口触发，断言交互前后状态发生预期变化；输出交互事件和前后状态。
- [ ] `Chest.ProducesItem`：断言产出物数量或背包/掉落状态符合现有预期，输出物品 ID、数量、位置或背包前后计数。
- [ ] 场景数量为 0 时必须明确输出 `count=0` 并使相应功能断言失败或阻塞；不得写成“代码/预制体不存在”，也不得仅因找到资产而判通过。

### 子项 8：迷雾

至少实现并输出：

- [ ] `Fog.MaskState`：定位实际遮罩组件，输出对象路径、组件类型、`activeSelf/activeInHierarchy`、enabled，以及实现中可取得的透明度/可见性状态；断言 Play 中遮罩状态符合当前预期。
- [ ] `Fog.EnemyVisibility`：输出敌人 ID、位置、视野内/外判定及渲染可见状态，断言视野外敌人隐藏、进入视野后按现有规则显示。
- [ ] `Fog.VisionClearing`：角色移动前后输出角色位置、视野半径及角色周围与范围外的遮罩采样/组件数据，断言视野范围内遮罩被清除且范围外保持符合规则。
- [ ] 新差距“Play 中遮罩未显示”必须以组件和数据复核，不得仅凭组件 active 推断画面一定可见；无法由数据覆盖的部分只留给第 5 节目检。

### 子项 9：救援（现状行为）

至少实现并输出：

- [ ] `Rescue.Fixture`：建立 1 个倒地角色和 1 个可行动角色，输出双方 ID、位置、距离和前后状态。可用夹具安排倒地，但不得直接调用救援完成方法代替触发。
- [ ] `Rescue.AutoTrigger`：通过实际靠近/距离条件触发，断言未使用目标点击流程时是否自动开始救援；输出触发时间、距离和事件链。
- [ ] `Rescue.Completes`：断言救援在限定时间内完成，输出倒地/行动状态、进度、完成事件及最终状态。
- [ ] 只验当前自动救援，不断言“悬停图标→点击指令”的目标需求，不让全员倒地。
