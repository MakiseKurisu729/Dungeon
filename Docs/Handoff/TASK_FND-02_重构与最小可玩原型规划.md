## 5. MVP 最小闭环

**流程骨架：走图 → 遇怪 → 普攻战斗 → 宝箱 → 全员倒地/游戏结束 → 按 R 重来。**

1. **走图**：直接从 `DungeonWorld` 进入游戏，既有三角色可通过真实右键指令沿 NavMesh 移动；不要求新整备流程。
2. **遇怪**：正式场景中至少有 1 个可复现的既有普通敌人遭遇；记录 ID、位置、存活与导航状态，不再以长时间零遭遇作为未知背景。
3. **普攻战斗**：至少一名玩家能通过真实指令接敌并持续普攻；伤害经现有生命入口结算，敌人可受击/死亡，基础动画与逻辑状态一致。技能不作为 MVP 门槛。
4. **宝箱**：正式场景中至少有 1 个既有宝箱；通过真实交互入口开启，产出只结算一次并留下可断言结果。
5. **团灭与结束**：三名玩家全员倒地后，产品路径在限定时间内只触发一次结束状态与可见提示，不依赖测试补写 `GameStarted`。
6. **重来**：真实按 `R` 后重新开始同一单场景局；玩家、敌人、宝箱、相机焦点、输入、`timeScale` 和局内事件订阅回到确定的初始状态，无重复结算。
7. **完成定义**：以上链路自动断言连续运行 2 次一致，必要人工目检不超过 3 项；原始日志、断言数据与复验记录齐全。

MVP 不要求胜利结算、撤离、跨层、成长或多人联机；宝箱开启后继续探索即可，失败—重来是本阶段唯一完整局循环。

## 6. 重构范围与禁区

### 6.1 仅圈以下 MVP 触达系统

- `DungeonWorld` 的最小组合/启动接线，以及局内 `GameStarted` 生命周期。
- 既有玩家移动、普通敌人固定遭遇及其导航接线。
- 既有普攻、伤害/生命、倒地与 MVP 所需基础动画状态。
- 既有 `Chest` 的场景装配、真实交互和产出验证。
- `GameFlow`、最小 HUD 提示与 `R` 重开所必需的状态复位。
- 复用 FND-00B 自动验收入口与证据格式；按缺陷需要增补测试，不安装新测试包。

### 6.2 明确不做

- 不做全仓目录迁移、批量 `asmdef` 拆分、统一事件总线改造或一次性全量脚本/YAML 重写。
- 不借 MVP 实施完整 `UnitRegistry`、统一交互、完整技能解耦、三态共享迷雾或对象池改造；只有 MVP 缺陷证据表明必须做最小接口调整时，才另列小单审查。
- 不改目标救援、传送、Boss、三层地牢、Town/成长、联机或 Unity 6.3。
- 镜头、技能、迷雾保留在修复基线，不为“顺手清理”混入 MVP 工单；若实际阻断 MVP，只派最小修复单。
- 不把夹具通过、预制体存在或代码类型存在写成产品功能通过。
