## 4. 逐步验收清单

### 步骤 1：建立移动前状态

- [ ] 用户打开既有场景并进入 Play，只选中 1 个实际可操控角色，记录角色名称。
- [ ] 保存 `01_移动前.png` 与 `01_移动前_Console.png`，并把 Console 实际文本写入 `Unity_移动.log`。
- [ ] 记录起始位置或地面参照物，确保后续可辨认位置是否变化。

### 步骤 2：执行一次移动指令

- [ ] 用户对一处明确、可辨认的地面目标执行 1 次现有移动输入（建议右键点击地面；以实际输入为准并记录）。
- [ ] 保存 `02_移动指令后.png`，记录指令时间、目标位置或参照物。
- [ ] 只观察：角色是否响应、是否朝目标移动、路径是否明显异常、能否在目标附近停步，以及过程中镜头跟随是否正常。
- [ ] 不拖拽视角，不点击敌人，不触发技能；若立即报错或角色不移动，记录现场，不为通过而反复尝试。

### 步骤 3：记录结束状态与 Console

- [ ] 角色停步后，或已能判定未移动/异常后，保存 `03_移动结束.png` 与 `03_移动_Console.png`。
- [ ] 将实际 Console 文本追加到 `Unity_移动.log`；若复现 NavMesh 或 `GetRemainingDistance` 信息，须原样保留完整文本与堆栈。
- [ ] 用户退出 Play，不保存场景或资产变化。

### 步骤 4：填写 QA 与报告

在 QA 第 2 项至少记录：

```text
测试场景：Assets/Scenes/DungeonWorld.unity
验收提交：<完整 HEAD>
测试角色：<实际名称>
输入与目标：<实际输入、目标位置或参照物>

结果：<通过/部分通过/失败；未实际执行则未测试>
证据：<逐项列出真实存在的相对路径>
```

判定标准：

- **通过**：角色响应指令并移动到目标附近，路径与停步符合预期，过程中镜头跟随正常，且各阶段证据齐全。
- **部分通过**：已实际移动，但目标到达、路径、停步、镜头跟随或必要证据只有部分符合或只能部分确认；明确写出未确认项。
- **失败**：已实际下发指令，但角色不移动、移动行为明显不符合预期，或出现阻碍移动的报错。
- **未测试**：前置失败或未真实执行。
