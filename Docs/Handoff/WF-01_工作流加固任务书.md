你是【大脑】。本任务为流程规则加固（非游戏功能开发），基于 OpenCode 官方工作流五支柱与官方实战案例审查结果，将以下规则写入项目文件。本次特批你修改：仓库根目录 AGENTS.md、新建 .opencode/skills/ 目录、修改 opencode.json（如存在）、修改 Docs/00_项目事实基线.md。

效率约束：单项回复不超过 300 字；修改已有文件用最小 diff，禁止整文件重写；一次读完所需文件再动手；每完成一组告诉我改了哪些文件的哪一节。全部完成后更新 CURRENT.md 登记本批次。

## A. AGENTS.md 重构（最重要）

A1. 瘦身：全文控制在 200 行以内。超出部分细节规则移至 Docs/00_项目事实基线.md 或新建 Docs/Handoff/workflow-rules.md，AGENTS.md 只保留硬约束+索引指针。
A2. 新增「Do not」节，汇总全部禁止项：整文件重写；声称运行过未运行的验证；越权写文件（大脑只写 Docs/Handoff，执行者禁一切 git 写）；预填/编造用户未提供的验收结果。
A3. 新增「When stuck」节：工单信息不足→在 REPORT 声明"信息不足"，不得自行翻阅其他文档；无法复现→明确写"无法复现"并提出复现步骤，不得编造根因；需求矛盾→停下来向用户提问，不得自行取舍。
A4. 新增「诊断纪律」节（适用于所有修复类工单）：根因分析先行，禁止表面补丁；间歇性/时序类问题必须 N≥3 次重复运行验证（单次通过不算修复）；每条修复结论必须能追溯到证据（日志/断言/diff）。
A5. 新增「效率约束」节（沉淀现有口头规则）：
  - 大脑：单次回复≤300字；修改已有文件只输出改动部分；能一次读完的文件禁止分多轮小步读；大型文件（QA 表、REPORT）的创建与重大修改交执行者，你只读和小幅修订。
  - 执行者：禁止整文件读取日志/大文档，只用 grep/Select-String 定向提取（-Context 2），结果超 50 行只留计数+前 10 条示例。
A6. 新增「工单自包含原则」：TASK 文件必须包含执行者完成任务的所需全部信息（背景、约束、验收标准、输出路径），禁止写"参见 CURRENT.md"式指针。
A7. 验收标准节补充：间歇性问题重复运行次数由 2 次改为 N≥3。

## B. FND-02 重构期规则（写入事实基线"工作流约定"节）

B1. 影响面清单确认闸门：所有涉及代码/资产修改的工单，执行者在动手编辑前必须先输出"受影响文件与符号清单"（含字符串引用、场景引用），等用户确认后才可编辑。
B2. Unity 专属警告（写入每张 FND-02 工单的固定节）：重命名类或移动文件必须连同 .meta 一起；Animator 参数名、SendMessage、GameObject.Find("名字") 等字符串引用必须单列核查清单；场景/预制体中的组件引用走 GUID，重构后必须验证引用未断裂。
B3. 提案闸门：每张 FND-02 工单先生成提案（业务规则+未决问题清单），用户回复"批准"后才生成正式 TASK 文件。
B4. TDD 前置：修复类工单执行顺序改为"先写失败测试（red）→再实现到全绿"；新功能同。测试资产沿用 Assets/_Project/Tests/ 体系。
