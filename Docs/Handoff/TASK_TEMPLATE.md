> 本模板 = 课程 `specs/<feature>/{requirements, plan, validation}.md` 三文件的本项目合并版。
> 用法：复制为 `Docs/Handoff/TASK_<ID>.md`，逐节填写，删除本说明与所有 `<占位>`。
> 规则来源：`AGENTS.md`（硬约束）、`Docs/Handoff/workflow-rules.md`（细则）。

| 字段 | 值 |

## §1 需求（Why / What）

**一句话目标**：完成后仓库 / 产品多出什么**可验证**的东西。

**用户故事**：作为 `<角色>`，我要 `<能力>`，以便 `<价值>`。

**必须满足**

| 编号 | 需求 | 验收方式 |
|---|---|---|
| R-1 | … | 自动化断言 / 目检 |

**不在范围**：逐项列出本次不做的事，防范围蔓延。

**约束**：适用的架构不变量（`Docs/01` §1.4）、ADR 编号、公共字段与序列化兼容、性能上限。

## §2 方案（Plan）

**备选方案**（至少两个；只有一个可行时说明原因，不省略对比）

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A | … | … | … | 弃用，因为… |
| B | … | … | … | **选定**，因为… |

**选定方案与理由**：一句话说清为什么是它。

**数据流**：`输入 → 处理 → 输出`（谁触发、经过哪些类 / 资产、结果落到哪里）。

**影响面清单**

| 项 | 内容 |
|---|---|
| 新增文件 | 路径 + 用途 |
| 修改符号 | 类 / 方法 / 字段 |
| 字符串引用 | Animator 参数名、`SendMessage`、`GameObject.Find`、事件名 |
| 场景 / 预制体引用 | 走 GUID 的对象与组件 |
| `.meta` | 是否随资产移动 / 重命名 |

**实施顺序**：1. … 2. … 3. …

**风险与回滚**：最可能出错的点、如何检测、回滚锚。

## §3 验证（Validation）

**AC 表**（每条必须可断言）

| AC | Given / When / Then | 断言 ID | 证据 |
|---|---|---|---|
| AC-1 | 给定…，当…，则… | `Skill.CastSmoke` | `Docs/QA/Evidence/<ID>/…` |

**运行次数**：常规同一入口连续 ≥2 次；间歇 / 时序类 **N≥3**。

**自动化优先**：修复 / 功能单先写失败测试（red）→ 实现到全绿（green）；无法自动化的目检 **≤3 项**，须写明理由。

**必须保存的证据**：运行日志、JSONL、`Summary.md`、`ExitCode.txt`，路径填在 AC 表“证据”列。
