## 4. 第 4 项：普攻自动化验收标准

### 4.1 前置与真实指令

- [ ] `Attack.Fixture`：记录所选玩家、既有普通敌人预制体来源、双方 ID/队伍/位置/生命、目标存活与可选中状态、双方 Agent 导航状态。场景无敌人时只在内存实例化既有敌人作为目标夹具，并明确标注。
- [ ] 通过生产选择入口选中玩家；定位真实鼠标攻击指令所调用的生产命令入口，记录脚本、方法签名和调用链。允许使用生产选择/命令方法作自动等价输入，**不得逐帧调用攻击执行器或直接扣血**。
- [ ] `Attack.CommandAccepted`：下发一次真实普攻命令，断言命令被接受且目标正确；无法定位入口或命令阻塞时输出 `blocked`，保留第 4 项未测试，不实施修复。
- [ ] `Attack.Approach`：由现有命令/移动链接近至实际攻击范围，输出起止距离、配置范围、路径与耗时；不得用测试 Warp 玩家来冒充接敌。

### 4.2 出招、持续攻击与伤害

- [ ] `Attack.Starts`：观察到实际出招事件/状态，记录首次出招时间、动作标识与目标；仅靠近但未出招为产品失败。
- [ ] `Attack.Repeats`：在固定观察窗口内至少出现 **2 次**有效攻击结算，输出每次时间、间隔及 `UnitStats.attackSpeed` 对应预期；不得以动画播放次数替代伤害次数。
- [ ] `Attack.DamageResolved`：每次有效命中经既有生命/伤害入口结算，记录目标 HP 前后值、结算伤害、事件顺序与累计次数；测试不得直接写 HP。
- [ ] `Attack.TargetDeath`：若观察窗口内目标死亡，记录死亡事件仅一次、后续不再重复结算；未死亡则记录最终 HP 和“不覆盖死亡”，不据此单独判普攻失败。
- [ ] 两次运行均输出相同断言集合。普攻全部必需产品断言通过才可判 `通过`；已建立有效前置后出现不出招、不持续或伤害不结算判 `失败`；入口/夹具前置无法建立且未执行实际普攻判 `未测试`。

## 5. 第 6 项：角色动画自动化验收标准

- [ ] 只读确认当前 Animator Controller/Override 的状态名或状态哈希、参数与预期映射并记录；不得凭名称猜测播放成功。
- [ ] 每次采样输出角色、逻辑状态、Animator 状态名/哈希、`normalizedTime`、相关参数和对应生产事件；屏幕外仍须可读数据。
- [ ] `Animation.Idle`：无指令时观察待机/Locomotion 状态与参数，断言和实际逻辑一致。
- [ ] `Animation.Move`：使用既有移动命令，观察移动状态/混合参数；复用第 4 项接近过程，不另判移动 QA。
- [ ] `Animation.Attack`：与实际出招和伤害时序对照，断言进入既有攻击状态；不得直接设置攻击触发器。
- [ ] `Animation.Hit`：在独立动画夹具中通过生产 `UnitHealth.ApplyDamage` 施加一次非致命伤害，观察受击状态/事件；该伤害只作动画刺激，不计入第 4 项普攻结算。
- [ ] `Animation.DownedOrDeath`：仅对一名夹具角色通过生产伤害入口施加致命伤害，记录 `dead/isDown` 与实际 Animator 状态；当前玩家以倒地表现代替彻底死亡时按真实设计记录，不制造全员团灭。
- [ ] 五类状态全部通过判 `通过`；已实际触发但状态不进入、明显不匹配或逻辑/动画断言失败判 `失败`；无产品失败但仅部分状态取得有效观察判 `部分通过`；全部因前置阻塞未观察判 `未测试`。逐项列出未覆盖状态，不得静默跳过。
