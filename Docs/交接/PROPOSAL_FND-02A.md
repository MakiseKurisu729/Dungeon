## 1. 提案目标与事实边界

### 1.1 唯一结果

进入真实 `DungeonWorld` Play 后，产品流程无需测试代写状态即明确开局；正式场景保存 1 个可复现的既有普通敌人固定遭遇，玩家可经现有移动指令接近，为 FND-02B 提供真实战斗前置。

### 1.2 已知事实

- `GameFlow.Start()` 当前将静态 `GameStarted` 置为 `false`；`Update()` 在未开局时直接返回。
- 既有 `MainMenuPanel.OnClose()` 会恢复 `timeScale=1` 并置 `GameStarted=true`，但 FND-00B-05 实测主菜单未接线，产品路径未开局。
- FND-00B-05 实测正式场景怪物 0、生成器 0、20s 新增 0；不得把原因写成已确认结论。
- `Assets/_Project/Prefabs/Skeleton_Warrior.prefab` 存在。FND-00B-06 曾用其内存实例在约 `(-2.72, 0.08333, 7)` 建立夹具，玩家从约 `(-2.72, 0.08333, 0)` 经生产命令链正常接近；该历史结果不代替本单真实场景验收。
- FND-01 后真实右键移动已由用户人工验收通过。

### 1.3 非目标

不修普攻、伤害、动画、镜头、技能、迷雾、宝箱、救援、传送或团灭/重来；不开发通用刷怪器、随机生成、Boot/Town、新主菜单流程或 `UnitRegistry`；不升级 Unity、不安装包、不做全场景整理。

## 2. 业务规则（提案）

| ID | 规则 |
|---|---|
| BR-01 | MVP 从 `DungeonWorld` 进入 Play 后直接自动开局，不要求点击主菜单；开局必须由产品代码完成，测试不得写 `GameStarted` 或调用测试专用后门。 |
| BR-02 | 每次场景启动只发生一次 `false → true` 开局；稳定后 `GameStarted=true`、`timeScale=1`，既有 3 名玩家保持不变，不重复生成单位或重复订阅事件。 |
| BR-03 | 正式场景保存且仅新增 1 个 `Skeleton_Warrior` 普通敌人；使用既有预制体及其生产参数，启用既有 AI/生命/导航组件，不使用内存夹具替代产品断言。 |
| BR-04 | 固定遭遇位置确定、两次运行一致，出生点位于 NavMesh 可导航区域并可从玩家出生区接近；不新增随机偏移、运行时刷怪器或测试 Warp。 |
| BR-05 | 本单只证明“产品已开局、固定遭遇存在且可接近”。敌人受击/死亡、玩家普攻、动画与团灭留给后续工单，本单不得借通过接近断言宣称战斗通过。 |
| BR-06 | 保留现有移动、伤害和场景其他内容；除已证实必需的启动接线外，不调整公共状态机、预制体默认值或 UI 架构。 |

## 5. TDD 测试先行设计

### 5.1 顺序

1. 用户批准本提案后，【大脑】才生成正式 TASK；执行者先提交最终“受影响文件与符号清单”，用户再次确认，并明确关闭 Unity。
2. **只新增测试资产**，在尚未修改生产场景/脚本时运行 red。有效 red 至少证明 `Startup.ProductEntry` 与 `Encounter.SceneCensus` 因当前产品状态失败；测试基础设施错误不算有效 red。
3. 保存 red 断言、原始日志和退出码后才允许最小生产编辑。实现后使用同一入口运行 green，连续 **2 次**判定一致；若暴露间歇性/时序问题，相关验证增至 **N≥3**。
4. 旧 FND-00B 的“场景怪物 0”是历史前置，不得篡改旧 QA/证据来适配新场景；本单使用独立 FND-02A 断言，并保留 FND-01 移动回归。

### 5.2 产品断言

| 断言 ID | 客观预期 | 必留数据 |
|---|---|---|
| `Startup.ProductEntry` | 真实场景进入 Play、无任何测试状态写入后，产品自身令 `GameStarted=true`、`timeScale=1`，无主菜单阻塞 | 产品入口/调用链、状态采样、首帧与稳定时间、测试写入标志=false |
| `Startup.OnceAndStable` | 观察窗内仅 1 次开局上升沿；玩家仍为 3，敌人不重复生成，状态稳定 | 上升沿次数、单位 ID 清单、事件/订阅计数（可取得时）、观察时长 |
| `Encounter.SceneCensus` | 生产场景恰有本单新增的 1 个普通敌人，非测试内存夹具；无随机刷怪来源新增 | 敌人 ID、名称、路径、team、hp、active 状态、场景怪物/生成器计数 |
| `Encounter.FixedIdentity` | 敌人来源为批准的 `Skeleton_Warrior.prefab`，初始位置/旋转与批准值一致，两次运行一致 | 预制体 GUID、场景文件实例 ID、坐标、容差、两次采样 |
| `Encounter.NavMesh` | 敌人 Agent 启用且 `isOnNavMesh=true`，既有 AI 未被测试禁用 | Agent 状态、NavMesh 采样、brain 状态、异常计数 |
| `Encounter.RealApproach` | 通过现有选择/移动命令从玩家出生区接近固定遭遇；不使用 Warp 或直接写玩家坐标 | 方法签名、起止距离、路径状态、耗时、最大单帧位移、目标位置 |
| `Regression.NoNewErrors` | 无新增导航异常或阻塞性错误，既有玩家移动仍可用 | Console 分类计数、异常原文、FND-01 路线回归数据 |

1. 实施前记录完整 HEAD、工作区原始状态及生产文件精确 diff 起点；旧批次未提交改动先由用户处理，禁止在其上混合回滚。

5. 回滚后核对生产 diff 已回到本单前状态，并复验 FND-01 既有移动路线；回滚不要求 FND-02A 新断言继续通过，也不得把回滚写成验收通过。
