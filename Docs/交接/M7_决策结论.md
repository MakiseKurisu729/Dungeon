### 2.3 自动提交规则

1. **一步一提交**：一步 = 上表一行或 M7-2 一个子项；不按文件数拆。
2. **提交前**：`git status` 只有本步声明文件；编译/测试通过；证据已落盘。否则不提交。
3. **提交信息**：标题 + 两行正文，全部中文：

   ```text
   重构：M7-1 批1 Core+Content 目录与命名空间归一（M7-1/批1）
   为什么：先收口最底层，后续批次只改上层，避免跨层引用反复变动。
   验证：编译 0 error；REFACTOR 16/16；SPEC01 12/12；audit upward=11；证据 Docs/QA/Evidence/M7-1/批1/
   ```

4. **提交后**：`git show --stat` 记录 commit hash 到本步证据；`git log --oneline -1` 写进 REPORT。
5. **回退**：某步改坏时，优先 `git revert <自己的 commit>`；只回退本任务内自己的提交，不碰别人的提交，不改写历史。
6. **禁止**：`push`、`reset --hard`、`rebase`、`amend`、force push、`git add -A`、提交用户未提交的改动、提交场景/预制体/Animator/`.asset`/`ProjectSettings`/`Packages`。
7. **不提交的情况**：验证红、证据缺失、出现未声明文件、需要改资产、需要改任务外文件——停下报告。

### 2.4 回滚锚

1. `pre-m7` tag / 文档整理提交后的 HEAD（任务开始前）。
2. 每步 commit（`git log --oneline` 可查；提交信息带任务号/步骤）。
3. 每步 `Docs/QA/Evidence/M7-1/批N/` 证据与 `git show --stat` 记录。
4. 若某批失败且无法在允许轮次内修复：`git revert` 该批提交，恢复到上一批，写报告停止。

### 2.5 停止条件

- 计划外资产改动 / 装包 / 升 Unity / 超出 60 文件清单的目录迁移。
- `.meta` 删除+新增配对、场景 Missing、GUID 断裂。
- 编译错误连续 2 轮；单步重试 ≥3 次仍红。
- MCP 连续 3 次失败，或 `isCompiling` 超 10 分钟且唤醒无效。
- 测试连续 3 次红；`git status` 出现未声明文件。
- 发现第二个 AI/会话正在写同一 Unity 实例。
- 自动提交越界（push/reset/rebase/amend/提交未声明文件）。

5. 地牢门：黑屏过场 + 传送 + 相机正常。
6. 四套件：`REFACTOR` 16/16、`SPEC01` 12/12、`FND00B06` 12/0+2obs、`DIAG` 6/1（已知红不变）。
