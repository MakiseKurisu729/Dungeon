## 8. 工作流约定

### 自动化验收标准

1. 每个验收类工单必须包含固定节 **“自动化验收标准”**，逐项写明可断言的预期行为，包括前置条件或操作、客观断言、实际数据输出及原始日志位置。
2. 每个验收类工单必须单列 **人工目检清单**，仅保留不超过 3 项无法由自动化断言充分覆盖的必要视觉核对；没有则明确写“无”，不得以人工观感替代可自动化断言。
3. 验收与修复验证默认使用可重复运行的自动化测试并保留断言、数据和原始日志。一次性且不再复用的小验证可豁免，但必须在工单或报告中说明理由。
4. 重复运行次数：常规验收同一入口连续运行 ≥2 次；**间歇性/时序类问题必须 N≥3 次**，单次通过不算修复（WF-01 起生效，已派发的旧工单不追溯）。

### 文档命名与单一真相源（WF-01.1 新增）

1. 文件名必须带职责前缀：`TASK_` / `REPORT_` / `QA_` / `EVIDENCE_`（入口类 `CURRENT.md`、编号设计文档 `00`～`05` 除外）。
2. 同一工件全仓唯一路径，禁止跨目录同名；任务包统一位于 `Docs/Handoff/TASK_*.md`，原 `Docs/Tasks/` 已于 WF-01.1 并入并删除。
3. 两文件内容冲突时，以“当前状态”文件（`Docs/Handoff/CURRENT.md`）为准。

### FND-02 重构期规则（WF-01 新增）

1. **影响面清单确认闸门**：所有涉及代码/资产修改的工单，执行者在动手编辑前必须先输出“受影响文件与符号清单”（含字符串引用、场景引用），用户确认后才可编辑。
2. **Unity 专属警告**（每张 FND-02 工单必须含此固定节）：
   - 重命名类或移动文件必须连同 `.meta` 一起；
   - Animator 参数名、`SendMessage`、`GameObject.Find("名字")` 等字符串引用必须单列核查清单；
   - 场景/预制体中的组件引用走 GUID，重构后必须验证引用未断裂。
3. **提案闸门**：每张 FND-02 工单先生成提案（业务规则 + 未决问题清单），用户回复“批准”后才生成正式 TASK 文件。
4. **TDD 前置**：修复类与新功能工单执行顺序为“先写失败测试（red）→ 再实现到全绿”；测试资产沿用 `Assets/_Project/Tests/` 体系。
