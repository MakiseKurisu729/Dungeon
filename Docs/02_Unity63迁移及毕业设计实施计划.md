# 魔石地牢：Unity 6.3 迁移及毕业设计实施计划

> 文档版本：v1.0  
> 编制日期：2026-11-01  
> 计划周期：2026-11-02 至 2027-05-15  
> 依据：毕业设计任务书、当前仓库静态审查、《总体架构与内容生产规范》  
> 计划属性：执行基线；未完成的阶段均不得写成已有成果。

## 1. 交付目标与范围冻结

### 1.1 最终必须交付

1. Unity 6.3 LTS 可运行工程、Windows 演示构建和可复现启动说明。
2. 完整单机闭环：整备编队、进入、探索、战斗、搜集、双向激活式撤离、成功/失败结算、队伍成长。
3. 三层手工/模块化主题地牢，具有不同空间拓扑、区域功能、敌人组合、环境机制、资源分布和导航线索。
4. 最多 4 人编队与 RTS 式选择、移动、集火、技能和统一交互。
5. 至少 4 个可玩职业：现有三职业整合完成，并新增至少 1 个扩展职业用于证明扩展性；第 5 个职业为可选增益。
6. 共享战争迷雾、探索记忆、敌人显隐和跨层状态维护。
7. 普通/精英敌人、两类机制不同的多阶段首领，以及倒地救援与团灭判定。
8. 2～4 人 Host 模式房主权威 P2P 联机，不使用专用服务器。
9. 功能、边界、性能、玩法和联机测试记录，以及五项研究内容对应的数据与分析。
10. 架构、数据、场景、动画、测试、AI 交接文档与毕业论文材料。

### 1.2 不在本次范围内

程序生成地牢、攻城战、原创元素交互、DOTS/ECS、深度学习/神经网络、专用服务器、大型热更框架、商业化运营系统。不得用这些方向挤占核心内容工期。

### 1.3 建议内容上限

- 三层地牢各形成 10～15 分钟的有效探索内容，完整演示路线控制在约 35～50 分钟；另提供 5～10 分钟答辩直达演示配置。
- 普通/精英敌人以“行为差异”而不是数量为目标：复用现有四类骷髅，新增少量主题敌人即可。
- 两类首领分别突出多主体协作压力、动态场地/部位机制，避免只堆血量和伤害。
- 职业和技能优先完成扩展验证与队伍分工，不在末期无验收地增加大量技能。

## 3. 阶段实施计划

### 阶段 A：基线封存与迁移准备（11-02～11-08）

**任务**

- 为当前 2022.3 工程建立 `baseline/unity-2022-3` 标签或等价备份；保留可独立打开的旧版工程。
- 记录仓库提交、Unity 中国版准确版本、包清单、素材来源和许可证。
- 导出核心场景、预制体、控制器、数据资产和 Project Settings 清单。
- 建立迁移回归用例：三职业移动/普攻/技能、敌人 AI、伤害、宝箱、迷雾、镜头、暂停、场景传送；救援标记为待接线验收。
- 检查 Git 忽略规则，不提交 `Library`、`Temp`、`Logs`、`obj`、构建缓存和任何凭据。

**验收**

旧版基线可恢复；迁移用例有实际步骤和预期结果；没有直接用唯一工程副本进行升级。

### 阶段 B：Unity 6.3 迁移（11-09～11-22）

**顺序**

1. 创建 `migration/unity-6-3` 分支和独立工程副本。
2. 优先在独立副本中直接用 Unity 6.3 打开，先解决编译和包兼容，再处理美术与玩法；不在旧版分支同步加新功能。若跨版本资产转换严重阻塞，可用 Unity 6.0～6.2 作为中间转换副本，但中间版本不是最终交付环境。
3. 使用 Package Manager 推荐兼容版本，锁定 URP、AI Navigation、Input System、Cinemachine、Test Framework 等组合。
4. Cinemachine 2.x→3.x 单独提交：先修 API，再运行数据升级器，检查场景、预制体、动画/Timeline 引用和隐藏 `cm` 对象。
5. URP 单独回归：材质、透明、阴影、Volume、迷雾、预警圈、粒子和 Renderer 设置。Unity 6.3 已移除 URP Compatibility Mode，不把它作为长期回退方案；若存在自定义 Render Pass，应按 Render Graph 路径迁移。只在确需中间转换时，按官方说明于 Unity 6.0～6.2 临时处理。
6. 导航单独回归：Surface、Agent、Obstacle、Link、烘焙结果和多层落点。
7. 输入逐步迁移到 Input System；不在同一功能里永久保留旧 `Input.GetKeyDown` 与新动作双轨。
8. 比较迁移前后截图和 PlayMode 结果，冻结 6.3 包版本后再合入主开发线。

**回退条件**

若某一包阻塞超过 2 个开发日，先隔离该包和测试场景，不在全项目反复升级/降级；保留旧版基线并记录具体错误，不能以“编译过了”宣布迁移完成。

### 阶段 C：当前功能验收与核心解耦（11-23～12-20）

**任务包**

- 完成倒地救援接线、打断、复活和团灭测试；修复 `UnitHealth.dead` 与倒地状态混用风险。
- 验收 `PlayerBase + Override`：单层、两段普攻、触发器、攻速、回退时钟、受击/死亡/救援。
- 建立楼层级 `UnitRegistry`，替换战斗、迷雾、团灭和技能输入中的高频全场扫描。
- 统一交互契约，先迁移宝箱和救援，再迁移门/撤离；统一距离、读条、打断、占用和结果事件。
- 为 `SimplePool` 增加注册、归还和重置规范，将飘字、爆炸和短特效纳入。
- 引入 `AbilityContext`，先迁移盾击和强化斩，再迁移远程/火球；效果不再直调具体职业或 UI。
- 将 Boss 奖励、场地和召唤从 `BossBrain` 剥离，保留现有行为作为对照，不立即扩展复杂招式。

**验收**

现有三职业和敌人不因重构失去功能；新增一个测试交互物不需要修改选择器；同一测试技能可通过接口作用于不同单位；连续回收特效无状态残留。

### 阶段 D：开题、内容设计与评价方案（12-21～2027-01-08）

**设计产物**

- 三层区域有向图：关键路径、可选路径、休整节点、资源区、遭遇区、首领区、双向撤离和层间连接。
- 每层“空间规则一页纸”：拓扑、视线、垂直关系、环境机制、导航地标、敌人组合、资源与风险。
- 职业模型：职能、资源、空间行为、战术接口、武器动作、职业技能、专属能力和被动修正。
- 两类首领阶段图：行为主体、阶段条件、场地变化、招式调度、队伍应对、异常恢复。
- 测试方案：研究假设、指标、日志字段、队伍配置、路线和对照方法。

**验收**

开题中的研究问题能对应具体实现和测试，不把“使用某插件”写成研究方法；五项研究均至少有可采集指标。

### 阶段 E：战斗扩展与三层灰盒（01-09～02-01）

**战斗线**

- 完成职业、武器、能力、效果、状态和被动修正的数据边界。
- 统一施法验证、消耗、冷却、目标、动作时序、取消和结算。
- 以第四职业作为扩展测试：优先选择能验证新空间行为或支援机制的职业，而不是只换模型和数值。
- 完成状态叠加、协同触发上限、死亡/倒地中断和日志。
- 建立战斗测试场景和 EditMode/PlayMode 用例。

**关卡线**

- 完成模块 Pivot、连接口、碰撞、遮挡、NavMesh 和 Socket 规范。
- 三层均制作可行走灰盒，先做关键路径和撤离，再做可选区域和主题装饰。
- 进行多单位通行、视线、无效折返、地标识别、垂直关系和撤离距离测试。
- 将区域图、出生点、遭遇和撤离点配置化，不生成随机地图。

**迷雾线**

- 完成楼层隔离的三态共享迷雾和敌人显隐；统一感知来源。
- 验证集中探索与分头侦察的视野覆盖、支援距离和风险记录。

**阶段门槛**

第四职业不得迫使修改选择、HUD、伤害和存档核心；三层灰盒均可从入口走到撤离点，无必需的单单位窄口。

### 阶段 F：垂直切片与原型复核（02-02～03-01）

**必须完成**

- 选择一层完成“灰盒→主题模块→敌人→资源→迷雾→撤离”的垂直切片。
- 打通 Town/整备 → 楼层 → 搜集 → 撤离 → 结算 → 成长 → 再次进入。
- 完成一个首领的最小多阶段原型，包含阶段转换、至少两类行为主体或场地事件、统一预警和异常恢复。
- 完成一个精英敌人行为验证，决定使用 Unity Behavior 或轻量 C# 行为树，避免长期双轨。
- 提前进行最小双人网络验证：Host/Client 进入、单位生成、移动指令、伤害和撤离结果。该验证不是完整联机交付，而是防止四月才发现架构不可同步。
- 完成外文翻译和原型复核材料。

**验收**

新成员可按文档从干净克隆启动；完整单局无编辑器手工补救；双人最小测试有日志和构建证据。

### 阶段 G：单机内容生产（03-02～04-01）

按“系统可复用、内容逐层验收”推进，不允许三张地图同时进入不可测试的半成品状态。

1. **层域一**：完善基础探索、清晰地标、标准遭遇和首个撤离节奏，作为其他层的质量基准。
2. **层域二**：强化可选路径、垂直/遮挡关系、不同敌人组合和资源风险，复用模块规则但改变空间体验。
3. **层域三**：强化动态场地、复合遭遇和首领前节奏，不引入全新底层系统。
4. **职业与构筑**：基础三职业和至少一个扩展职业全部可用；完成职业/武器/能力组合和有限队伍协同。
5. **敌人**：普通与精英复用感知和动作框架；每层配置有明确职能与遭遇目的。
6. **首领一**：突出多行为主体、目标选择与队伍任务分工。
7. **首领二**：突出多部位或动态场地、阶段转换和应对策略变化。
8. **经济与成长**：完成战利品带出、失败损失、成长和再进入的数值闭环。

**每层验收顺序**

可达性 → 导航 → 迷雾 → 战斗 → 交互 → 撤离 → 表现 → 性能 → 数据记录。未通过前一项，不用美术装饰掩盖玩法问题。

### 阶段 H：完整联机与联调（04-02～04-20）

- 固化网络对象、内容 ID、命令和权威状态；用 Host 模式完成 2、3、4 人配置。
- 同步队伍选择、单位生成、移动/攻击/技能、伤害/状态、倒地救援、掉落、交互、首领阶段、迷雾、撤离和跨层。
- 处理重复指令、目标失效、交互竞争、客户端不可见但权威仍模拟、断线和重开。
- 使用 Multiplayer Play Mode/独立构建做多端回归，记录操作系统、网络条件和包版本。
- 性能优化只针对 Profiler 和网络数据证据，不在联调期重写成另一套架构。

**联机完成定义**

不是“两个玩家能看到彼此”，而是 2～4 人能完成同一局探索、战斗、救援、撤离和结算，且关键结果一致。

### 阶段 I：测试、评价与优化（04-21～05-01）

- 冻结候选构建和内容 ID，执行完整测试矩阵。
- 进行不同队伍配置、路线和集中/分散探索对照；保存原始日志。
- 统计路线时间、无效折返、地标识别、战斗时长、资源损耗、倒地频率、撤离率和路径选择。
- 记录新增职业/敌人/交互/楼层的实际修改文件和工时，用于证明扩展性。
- 修复阻断、高优先级和可复现中优先级问题；低优先级表现问题进入已知问题清单。

### 阶段 J：论文与答辩（05-02～05-15）

- 05-02～05-07：以架构、实现和真实测试数据撰写论文，不补写未实现功能。
- 05-08～05-10：形成初稿，核对图表、引用、实验版本和数据。
- 05-11～05-13：修改定稿，冻结最终构建，准备完整流程和短途演示两条路线。
- 05-14～05-15：备份工程、构建、文档、视频和答辩材料；在一台干净环境按说明复验。

## 4. 五条研究线的实施与证据

| 研究线 | 最小实现 | 对照/测试 | 论文证据 |
|---|---|---|---|
| 多层空间建模与信息引导 | 区域图、模块规范、三层灰盒和正式场景 | 路线完成、折返、地标、视线与可达性 | 区域图、参数表、路线热区/记录、迭代前后对比 |
| 共享感知与探索决策 | 三态迷雾、遮挡、共享显隐、跨层数据 | 集中/分头、复杂遮挡、高差、门状态变化 | 可见性正确率用例、覆盖范围、支援距离与遭遇结果 |
| 多职业协同扩展 | 职业/武器/能力/状态拆分、第四职业 | 不同编队、新增职业扩展、状态组合 | 修改范围、工时、规则一致性、队伍职能和战斗数据 |
| 动态首领行为控制 | 阶段机、动作调度、场地/召唤/部位、预警 | 不同编队、阶段中断、重复进入、异常恢复 | 阶段图、动作日志、应对策略、战斗时长与倒地数据 |
| 节奏与风险收益评价 | 区域/遭遇/资源/撤离参数和日志 | 关键/可选路径、层间递进、参数迭代 | 强度曲线、资源损耗、撤离率、参数—行为对应表 |

不得只以“玩家觉得不错”作为研究结论；主观评价必须和可复现过程数据分开呈现。

## 5. 工作流与并行规则

### 5.1 四条工作线

- **工程线**：迁移、核心架构、战斗、交互、网络、测试。
- **内容线**：区域图、灰盒、模块、预制体、材质、动画、敌人与首领配置。
- **研究线**：文献、指标、实验、数据分析和论文。
- **交接线**：事实基线、ADR、任务包、验收证据和版本说明。

### 5.2 可并行与不可并行

可并行：文档与灰盒、材质规范与核心解耦、测试工具与内容设计。  
不可并行：同一 Animator Controller 多人同时修改、同一主场景大规模并行编辑、包版本升级与核心重构混在一个提交、网络接入时重写伤害底层。

### 5.3 每个任务的标准闭环

任务包 → 基线确认 → 小步实现 → 自动/手动测试 → 截图或日志 → 文档同步 → 提交 → 独立审查。  
未通过验收的功能保持“进行中”，不能因代码已写入就标为完成。

## 7. 测试矩阵

### 7.1 每次核心提交的最小回归

- 工程编译、正式场景启动、无缺失脚本和关键空引用。
- 三职业选择、移动、普攻、技能、受击和死亡/倒地。
- 普通敌人感知、追击、攻击、受控和死亡。
- 宝箱/救援/门或撤离交互的接近、执行、打断和完成。
- 迷雾三态、遮挡和敌人显隐。
- 对象池重复借还、场景重开无事件重复订阅。
- 动画时钟与代码回退均只结算一次。

### 7.2 里程碑专项

- 导航：4 单位窄口、拥堵、动态障碍、跨层落点。
- 战斗：同帧伤害、护盾/减伤、状态叠加、取消返还、目标死亡。
- 首领：阶段中打断、召唤物存活、危险区清理、奖励只发一次。
- 撤离：未激活、激活、双向使用、队友倒地、携带战利品、跨层返回。
- 联机：2/3/4 人、重复 RPC、并发交互、断线、重开、房主退出。
- 存档：空存档、旧版本、缺失内容 ID、损坏文件和写入失败。

## 8. 风险与应对

| 风险 | 预警信号 | 应对 |
|---|---|---|
| Unity 6.3 包/材质回归 | 编译通过但画面、镜头或动画异常 | 独立迁移分支、按包小提交、截图与 PlayMode 对照；保留旧版 |
| 联机末期返工 | 玩法直接读写场景对象和静态类 | 二月做最小双人验证；统一命令和 ID；四月只扩展不重来 |
| 内容范围过大 | 三层同时半成品、职业数量增加但无验收 | 单层垂直切片先行；砍可选职业/装饰，不砍核心闭环 |
| 多单位导航不稳定 | 窄口拥堵、目的地每帧重置 | 灰盒先行、编队落点、目的地阈值、专项测试场景 |
| 迷雾与联机规则冲突 | 客户端不可见导致权威 AI 停止 | 表现显隐与逻辑模拟分离，统一权威感知服务 |
| 首领逻辑失控 | 阶段条件继续堆入 Update | 阶段/动作/遭遇/场地分层，转换专项测试 |
| AI 回退旧方案 | 恢复 UpperBody、旧 Input、旧目录 | 根文档防回退清单、任务包引用基线、提交审查 |
| 二进制资产冲突 | 场景/控制器反复覆盖 | 指定唯一负责人，小步保存，禁止 AI 无依据全量重写 YAML |
| 论文无数据 | 只保留最终版本截图 | 从一月开始记录指标、版本、参数和原始日志 |

## 9. 延期时的范围裁剪顺序

依次削减：第五个及以后职业 → 额外敌人和隐藏区域 → 非关键演出与复杂光照 → 可选协同和装饰性成长。  
不得削减：Unity 6.3 可运行基线、完整搜打撤闭环、三层地牢、至少一个真实扩展职业、两类多阶段首领、共享迷雾、2～4 人 P2P、核心测试和论文数据。
