# ADR-0003 — 技能动画槽位化与子状态机

- 状态：`Accepted`
- 日期：2026-11-05
- 决策者：用户（产品决策）
- 相关：`Docs/01_总体架构与内容生产规范.md` §1.4 与 §11；替代 `Docs/Archive/03_AI协作与项目交接文档.md` §12 第 2、3 条（技能与 Any State 限制）的一部分

## 背景

现有动画方案把“普攻两段”与“技能”压在同一层状态里：普攻用 `Attack_Draw → Attack_Release` 的固定状态对，技能共用单个 `Skill` 状态。结果是：

- 多段技能无法表达，只能把多段动作烘进一个 Clip，命中窗口与打断点被埋进动画，代码难以按段控制；
- 远程普攻的“抬手 → 出手”同样被烘成单 Clip，命中帧与表现耦合；
- 所有技能都走同一条 Any State 之外的路径，切换技能必须改公共图，违背“新增内容不复制/不改核心”的扩展性要求。

## 决策

1. **技能槽 = 子状态机**：Q / W / E / R 各为一个槽子状态机；槽内**每段一个状态、一个 Clip**，支持多段技能（段间用退出条件/触发器衔接）。
2. **远程普攻 `AttackRange` = 子状态机**：内部保持 `Draw → Release` 两状态，**不再烘成单 Clip**；近战仍走 `AttackMelee`。
3. **技能槽允许 `AnyState → 槽`**，`Has Exit Time = 0`，可打断普攻；这是唯一放开的 Any State 入口，其余 Any State 仍只限受击/死亡，且禁止自过渡。
4. **命中帧归一化**：命中窗口继续以所在状态的 `normalizedTime` 比例表达，逐段配置，不以 AnimationEvent 作主命中路径；读取失败回退代码时钟。
5. **覆盖器按“槽的段”覆盖 Clip**：Override Controller 的覆盖项以“槽 + 段”为单位（如 `SkillQ_Seg1`、`AttackRange_Release`），不按整张公共图整体替换。
6. **运行时换技能按槽换整组 Clip**：切换技能只重绑该槽的覆盖组，不改公共图结构、不改其他槽。

## 原因

- 把“技能数量”从图结构问题降级为数据/覆盖问题：新增技能只增 Clip 与覆盖组，公共图不动，符合 §1.4 不变量 8～10 的扩展性目标。
- 每段一状态使命中窗口、可取消窗口、打断规则可逐段声明，避免把时序写进 Clip 后无法在代码侧校验。
- `AttackRange` 保留 `Draw → Release` 顺序，与既有不变量（普攻两段、命中用 normalizedTime）一致，只是把它从单层状态改成子状态机承载。
- 技能槽放开 AnyState 是为了“技能随时可接、可打断普攻”的手感需求；把例外限定在槽上，避免受击/死亡的全局打断语义被稀释。

## 影响

**正面**

- 多段技能、远程普攻可按时序拆解与复用；覆盖器粒度贴合技能槽，换技能代价低。
- 命中窗口可用自动化断言逐段校验，时序问题可按段定位。

**代价 / 风险**

- 公共图结构变化：需要一次性迁移现有 `Skill` / 远程普攻状态；迁移期间旧 Override 资产需同步重建（高风险，属用户管辖资产）。
- Any State 多入口后，需在验收中显式检查“受击/死亡打断优先级”与“技能互相打断”两类冲突。
- 段的命名一旦上线即成为兼容契约（覆盖器按名覆盖），改名需 ADR 或迁移脚本。

## 回滚

- 回滚锚：采用本 ADR 前的最后一次已验收提交（含 `PlayerBase.controller` 与相关 Override 资产）。
- 回滚方式：资产回退到该提交的 Controller / Override，代码侧保留“命中归一化”与“逐段窗口”读取（对旧单 Clip 方案仍成立），不保留槽子状态机的迁移脚本。
- 回滚后 `Docs/01_总体架构与内容生产规范.md` §1.4 的动画例外条目需同步删除，并在此标注 `Superseded`。
