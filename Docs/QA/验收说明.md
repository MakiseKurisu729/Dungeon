# 验收 — 真实验收记录

本目录只记录**真实执行过的验收结果**。

## 基本规则

- "代码存在"、"以前能用"、"理论上通过"**都不等于验收通过**。
- 没有实际操作过的项目，只能写 `未测试`。
- 结果只能使用以下四种：`通过`、`失败`、`部分通过`、`未测试`。
- 不伪造测试日期、截图、日志、控制台输出或通过结论。
- 一次验收对应一份记录文件，文件名建议 `任务ID_主题.md`。

## 记录格式

每项使用统一字段：

| 字段 | 说明 |
|---|---|
| 测试场景 | 场景名称 / 构建版本 / Unity 版本 |
| 前置状态 | 开始操作前必须满足的条件 |
| 操作步骤 | 可复现的步骤序列 |
| 预期结果 | 产品定义上的正确表现 |
| 实际结果 | 实际观察到的现象（只写现象，不写推测） |
| 结果 | `通过` / `失败` / `部分通过` / `未测试` |
| 证据 | 指向 `Evidence/` 下文件的相对路径 |
| 备注 | 阻塞、环境异常、待确认点 |

## 证据

- 截图、视频、日志统一存放在 `Evidence/`。
- 在记录中使用**相对路径**链接，例如 `Evidence/FND-00B_移动_2026-11-05_01.png`。
- 证据缺失时，在"证据"字段写 `无`，并在备注说明是否仅口头确认。

## 当前记录

验收记录按任务分散在 `Docs/QA/` 与 `Docs/QA/Evidence/`；当前套件基线与已知红见 `Docs/交接/当前状态.md`。历史记录保留原文件名与结论，不覆盖。
