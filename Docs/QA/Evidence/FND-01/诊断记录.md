## 2. 三类候选原因逐项结论

### 2.1 场景未烘焙 —— **已确认（主因）**

- 场景 `NavMeshSettings.m_NavMeshData` 为 `{fileID: 0}`，即**场景没有加载任何 NavMesh 数据**。
- 场景文件中不存在 `NavMeshSurface` 组件。
- 场景所有 GameObject 的 `m_StaticEditorFlags` 均为 `0`（无 `NavigationStatic` 位）。
- 结论：当前场景没有任何可加载的烘焙结果，属于“未烘焙/数据未挂载”。

### 2.2 NavMeshSurface 未激活 —— **已排除**

- 全工程 `Assets/**/*.unity`、`*.prefab` 中 `NavMeshSurface` 出现次数为 0。
- 不存在“有 Surface 但对象/组件未激活”的情况；本场景不使用 Surface 工作流。

### 2.3 烘焙数据丢失 —— **部分命中：数据文件存在但引用断裂**

- `Assets/Scenes/DungeonWorld/NavMesh.asset` **存在**，14652 字节，可被 Unity 作为 `NavMeshData` 资产识别；`.meta` GUID `fea05cc92de5b1d40b9a472821cb585a`，`mainObjectFileID: 23800000`。
- 二进制内含 `VAND` 瓦片数据：共 **36 个瓦片**（偏移 6172–14292，等距 232 字节），瓦片坐标从 `-3,-3` 起，覆盖约 `-100…+100` 的 200×200 地面范围 → 与 `ForestGround`（Plane，scale 20×1×20 = 200×200）吻合。
- 但该 GUID **在整个工程中被引用 0 次**（`git grep`、全 Assets 文本检索均只命中 `.meta` 自身）；场景 `m_NavMeshData` 为空。
- 结论：不是“文件缺失”，而是**场景引用断裂**：烘焙数据仍在，但场景没有指向它。

### 2.4 三类之外

- 排除“NavMeshAreas/导航层配置缺失”：`ProjectSettings/NavMeshAreas.asset` 存在且默认 `Humanoid` agent 配置完整。
- `NavMeshObstacle` 挖洞设计（`ForestGenerator`）不影响地面烘焙是否存在。
