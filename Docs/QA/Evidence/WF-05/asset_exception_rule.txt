=== AGENTS.md §3.3 资产管辖权（第 52-55 行）===

3. **资产管辖权**：场景、预制体、Animator Controller、`.asset` 归用户；AI 只出“改动清单/编辑器工具”，不直接改 YAML、不批量猜改 GUID。
   - **例外通道（所有者 2026-11-05 授权）**：AI 确需改资产时，允许提出，但必须按顺序走完三步——① 输出《资产改动清单》（文件 / 字段或组件 / 理由 / 回滚方式 / 影响面）；② 交大脑复核；③ 所有者明确批准。三步齐了才可用 Unity 编辑器或 MCP 工具执行，执行后必须读回验证并写进 REPORT。
   - **批准记录**：批准可能发生在大脑会话、也可能发生在子代理会话。子代理拿到批准后，必须在回执与 REPORT 里写明“谁批准 / 时间 / 批准内容”，否则大脑有权按未授权处理并要求回滚。
   - 仍禁止：手改 `.prefab`/`.unity`/`.asset` 的 YAML、批量猜改 GUID、绕过编辑器直接写序列化文件。

=== Docs/Handoff/workflow-rules.md §5.3 资产改动清单格式（第 205-218 行）===

### 5.3 资产改动清单格式

| 资产 | 路径 | 改动 | 风险 | 执行人 |
|---|---|---|---|---|
| 场景 / 预制体 / Animator / `.asset` | … | 字段 / 状态 / 引用 | GUID 或引用断裂 | 用户（AI 只出清单或编辑器工具） |

资产改动审批流程（所有者 2026-11-05 定）：

1. **出清单**：AI 按上表格式列出文件名、字段/组件、改动前后值、理由、回滚方式、影响面（是否动 GUID、是否影响场景引用）。
2. **大脑复核**：确认是否确有必要、是否可用代码替代、是否触碰架构不变量（触碰则先写 ADR）。
3. **所有者批准**：明确回复“批准”，或直接在子代理会话里批准。
4. **执行 + 读回**：批准后用 Unity 编辑器 / MCP 工具改，改完读回字段值并写进 REPORT；未批准的清单只能停留在提案状态。

补充：子代理在子会话里拿到的批准，必须在 REPORT 与回执中记录“谁批准 / 时间 / 内容”，大脑据此判断是否放行，不得只写“经批准”。

- 未调用 Unity 或 MCP。
