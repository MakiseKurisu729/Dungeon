## B. 独立次生根因（W 键历史失效）：`W_Slash_Effect.asset` 运行期被解析为 `BashEffect`

### B.1 证据锚点（`Diag.CastChain.W`，run1/2/3 一致）
- `effectType = "BashEffect"`（期望 `HeavySlashEffect`）；
- `Cast(1, null)` 返回 **false**；
- 但 `manaDelta = 30`、`manaBefore=100 → manaAfter=70` → **白扣蓝**（`SkillSystem.Cast` 先扣蓝后 `CanCast`，见未决项）；
- `cdRemaining=0`、`swordTimer=-1`、Animator 未进入 `Skill`。

### B.2 根因
- `Assets/_Project/Scripts/Combat/SkillEffects.cs` 同时定义 `BashEffect`（第一个类）与 `HeavySlashEffect`（第二个类）。
- 两个效果资产都引用**同一个** MonoScript：`m_Script: {fileID: 11500000, guid: b87811a1f9107cc43b6bc8cb79537544}`。
- `fileID: 11500000` 是该 .cs 文件的**主 MonoScript**（`BashEffect`）；`m_EditorClassIdentifier: Assembly-CSharp::HeavySlashEffect` 只影响编辑器显示，**运行期不参与类型解析**。
- 因此 `W_Slash_Effect.asset` 实际实例化为 `BashEffect`；`BashEffect.CanCast(null)` 需要目标 → 返回 false。
- 侧证：该资产 `needTarget: 1`，与 `BashEffect` 的语义一致；`HeavySlashEffect` 构造函数会令 `needTarget=false`。

### B.3 需要的改动（代码 + 资产，**需所有者单独批准**；本单未执行）
目标：让 `W_Slash_Effect.asset` 的 `m_Script` 指向一个**文件名为类名**的 `HeavySlashEffect` 脚本。

1. 新建 `Assets/_Project/Scripts/Combat/HeavySlashEffect.cs`，内容为现 `SkillEffects.cs:77-89` 的类（`using UnityEngine;` + 类定义），从 `SkillEffects.cs` 中删除该类；
2. 将 `SkillEffects.cs` 重命名为 `BashEffect.cs`（连同 `.meta` 一起移动，保留 GUID `b87811a1f9107cc43b6bc8cb79537544`），使 `Q_Bash_Effect.asset` 仍解析为 `BashEffect`；
3. 在编辑器中让 `W_Slash_Effect.asset` 指向新脚本：
   - 方案 a（推荐）：删除并重建该资产（Create → Dungeon/Skill Effects/Heavy Slash），随后在 `W_HeavySlash.asset` 的 `effects[0]` 重新拖入；保留 `range: 2.5`（输入层指示器范围）即可；或
   - 方案 b：手工把该资产的 `m_Script` 改为新 `.cs` 的 GUID（新 `.cs.meta` 生成后读取），保留其余字段；
4. 运行 A.5 验收命令，期望 10/10、exit 0。

> 本单不执行上述步骤：它同时改动生产运行时代码与 `.asset`，超出本单授权（§3.4）。
> 若不修 B，`Skill.CastSmoke` 会持续红，这是**真实产品缺陷**，不得通过放宽测试转绿。
