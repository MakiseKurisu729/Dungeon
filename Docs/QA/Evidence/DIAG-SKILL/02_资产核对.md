## 6. `Cooldown` 序列化说明（影响 cd 期望）

`Assets/_Project/Scripts/Framework/Cooldown.cs`：`public struct Cooldown` **没有 `[System.Serializable]`**，Unity 不序列化该字段；因此 `SkillData.cooldown` 始终取 C# 字段初始化值 `new Cooldown { duration = 6f }`。
→ 即使 `Q_Bash.asset` / `W_HeavySlash.asset` YAML 中缺少 `cooldown:` 段，运行期 `CdTotal` 仍应为 6s。Step 3 探针会实测记录 `cdRemaining/cdTotal`。

## 8. 运行期纠正（Step 3 探针结论，优先于本文静态推断）
静态读取只能看到 `W_Slash_Effect.asset` 的 `m_EditorClassIdentifier: Assembly-CSharp::HeavySlashEffect`，**不能证明运行期类型**。
`Diag.CastChain.W` 实测 `effectType = "BashEffect"`（Cast=false、白扣 30 蓝）：
- `SkillEffects.cs` 同时定义 `BashEffect`（主类）与 `HeavySlashEffect`（次类）；
- 两个效果资产共用 `m_Script {fileID: 11500000, guid: b87811a1...}`，运行期只解析为该文件的主类 `BashEffect`；
- `m_EditorClassIdentifier` 只影响编辑器显示。
该问题与 `SkillInputController` 缺失是**两个独立资产缺陷**，详细修法见 `04_资产改动清单.md` §B。
